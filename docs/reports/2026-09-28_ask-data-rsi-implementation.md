# Fuju RSI 问数场景实施记录

日期：2026-09-28
状态：离线协议、可复制 Skill 与配置文件比较已接通；真实业务接入和配置独立验收尚未执行（2026-10-03 更新）

## 本轮完成

1. 问数目录先登记每个原题的来源、语义家族和 train/validation/test 用途。案例只引用来源；同源改写继承用途，同一家族不能跨集合。ready 题要求独立计算方法、证据、固定数据快照和业务口径版本，任一版本不符就不能作为已复核题。准备器输出 RSI v2 案例，冻结继续使用原有 Benchmark 摘要和角色边界。
2. 结构化评分核对完整列名、行数、重复行、排序、数值绝对容差与单位。实际结果必须明确标记全量；字段缺失或任务失败是运行或评分协议错误，不会被当成空集正确。多轮题的全部必要轮次都通过才得满分。
3. 行为题需要业务侧提供独立的行为判分函数。最终答复默认需要独立交付判分函数；只检查数据库结果时须在标准答案中明确声明不要求交付判分。被测系统自报一个行为标签不能自动证明回答正确。
4. 问数 Agent 的优化入口必须给出已冻结的开发包和共用验证账本。每次开始前预留基线与全部候选可能查看验证集的次数；失败、取消和重复候选不退还。账本按输入、来源和家族指纹跨实验、跨题集版本累计，并拒绝把旧训练来源改成验证来源。
5. 固定问数候选时，候选包带上账本中所有已见开发来源的指纹。独立验收继续使用现有的开发/验收重叠检查、验收历史和默认统计门槛。没有通过独立验收的开发提升保持不可采用。
6. `fuju-tune` Skill 已将问数流程单独路由到 `references/ask-data.md`。复制后的 `run_experiment.py` 接收冻结开发包和共用验证账本，并把校验后的开发包路径传给 factory；核心 `optimize/report` 命令也接受 `--ask-data-bundle` 供 factory 读取同一目录；`kind="ask-data"` 缺少任一项时在调用 runner 前失败，实验摘要只公开验证使用次数等元数据，候选生成侧仍只得到训练明细与验证汇总。现有通用 Agent 路径保持可用。

## 数据和运行接口

问数目录的来源字段为 id、kind、ref、familyId、split。每题提供稳定 id、sourceId、问题或有序 turns、覆盖标签、状态、预期和 oracle。oracle 的 verified=true 只是资料准备者声明已复核；代码能检查证据是否存在、版本是否一致，不能证明业务计算本身正确。

业务 runner 接收候选提示词和题目，返回 Prediction；其 output 中的每轮结果要包含 status、behavior，以及答数时的 result.columns、result.rows、result.complete。业务适配器负责从实际持久化结果读取全量数据、确认会话与轮次，并区分真实运行异常和有效的业务失败。行为题与最终答复的 judge 由业务侧实现，不能依赖模型自己的自评。

本地使用步骤和离线 SQLite 示例见项目根目录 README 的“问数场景”。示例只含两个合成来源，作用是检查协议链路。它没有真实问数 Agent、独立 holdout 或可推广的准确率结论。

## AgenticData-on-fire 接入可行性（只读检查，目标待确认）

现有 `eval/scripts/run_existing_business_questions.py` 会以普通业务用户创建会话、发送原始问题、识别任务失败并保存会话消息；它适合建立真实原版诊断。但脚本没有候选提示词参数，也把答案准确性保留为独立复核，因此不能直接当作 RSI 的候选比较 runner。

该项目已有 Agent 配置读写接口，`eval/src/workflow/steps/tuner_steps.py` 证明了写入、读回、回滚可行。不过配置作用于项目和业务，多个会话可能共用它。真正接入前需要独立的测试项目或会话级覆盖，串行运行候选，记录配置原值并确认恢复；仅有 `finally` 无法覆盖进程崩溃后的恢复。原版与候选也必须使用相同模型、数据快照、业务规则和权限。

`backend/api/routes/handles.py` 提供会话结果句柄和分页读取，响应带总行数、`has_more`，主库结果还带是否截断与总数是否精确。现有 SSE 解析结果和页面表格可能只含预览。适配器应按本轮任务对应的句柄取齐所有页，核对未截断和精确行数，再标记 `complete=true`；句柄过期或分页不全应记录运行/协议错误。当前还没有完成这个适配器，也没有用真实 Agent 跑基线或候选。

## 防过拟合的证据边界

验证次数上限由项目在首次使用前显式设定，本轮没有改变通用验收阈值。预留次数是保守计费：即使预算中断或候选重复，也不会把验证题重新当作未见题。多道同源改写仍属同一个来源或家族；重复运行提高稳定性，不增加独立来源数。

本机账本防止正常流程中的重复选优与无意改名。使用新目录、手改历史、虚报来源或同一人看过私有验收题后再包装成新题，均不在其保护范围。真正独立的 holdout 需要不同的资料持有人或 CI/账号边界。默认验收仍要求 30 个独立来源组；小样本只能证明已知回归或协议行为，不能宣称泛化收益。
