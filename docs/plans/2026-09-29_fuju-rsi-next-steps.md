# Fuju RSI 下一步推进计划

日期：2026-09-29
状态：2026-10-03 已实施首个本地切片（配置候选身份、隔离文件比较、普通文件交付和恢复材料）；真实问数接入与配置独立验收待完成。下文保留原推进顺序，不能将合成协议测试当作真实业务效果。

## 目标与当前起点

先把 Fuju RSI 做成能在一个真实问数项目里交付**配置改动**的 Skill：发现失败，提出限定范围的改动，让原版和候选在相同条件下重跑，核对完整结果，再交付可应用、可恢复的文件差异。移动问数 Benchmark 中优先考虑指标上下文、业务词典和项目规则；具体应改哪一项，由失败证据决定。

计划建立时已具备可复制 Skill、问数案例与评分、开发/验收用途边界、提示词候选实验，以及只读场景清单。2026-10-03 新增 `FileExperimentSpec` 与 `compare-files`，场景清单加入词典、项目规则、指标上下文的文件比较；目前只支持已给定候选的开发/回归验证，配置独立验收和正式发布未启用。合成 SQLite 演示及干净安装证明了协议路径；真实产品的配置候选重跑和完整结果读取尚无完成证据。

## 先做一条真实的最小闭环

以移动问数项目作为首个接入样本，先选**一个有来源的已知失败**。优先选择经业务人员确认、不会改变答案含义的别名或解释修正，作为首个词典/上下文候选。若实际失败需要改正式指标口径或跨指标规则，则先记录提案并取得业务确认，不为了跑通实验而直接改口径。

这条闭环应留下六份可复核材料：

1. **问题依据**：原始问题来源、失败现象、实际完整结果、独立核对方法及固定的数据/口径版本。私有题目和答案留在业务项目的受控环境。
2. **原版身份**：业务代码版本、配置源文件摘要、生成配置摘要、模型及权限条件、数据快照、评分器与 Benchmark 版本。
3. **候选身份**：允许修改的文件及字段、逐文件差异、所属类型、是否改变业务含义、生成步骤与摘要、恢复所需原版内容。多个共同生效的文件组成同一个候选。
4. **生效证明**：在独立测试项目或等效隔离环境应用候选；从实际运行入口读回已加载配置；崩溃后也能识别并恢复实验状态。共享配置不得影响其他会话。
5. **成对结果**：相同数据、模型、权限、超时和事先固定的评分方式下重跑原版与候选；读取会话各轮持久化全量结果及最终答复，分别报告答错、运行异常、结果不完整、费用和关键退步。
6. **交付说明**：普通配置差异、生成方法、适用范围、恢复方法、证据级别。开发集改善、独立验收通过和业务产品已生效分别标注。

先在有隔离能力的测试环境做上述闭环。没有可信独立验收题时，结果只写“开发/回归验证”，不写“可采用”或“真实业务收益”。

## 实施顺序

### 第一步：版本化配置候选

在共用内核建立候选包身份：`target` 类型、源文件及基线摘要、允许改动范围、差异、生成命令及产物摘要、语义分类、适配器版本和恢复信息。冻结前检查源文件未漂移、改动未越界、生成产物确实来自该候选；冻结后不能换文件内容。现有提示词接口保留兼容，用同一候选身份承载完整提示词。

首版只做业务项目已经实际加载的文件类型；不要先把每种可能的数据库、模型或编程语言写成统一插件。未知目标类型或缺少生成/恢复能力时明确拒绝进入可采用流程。

**完成条件**：相同候选有稳定身份；改文件、改生成产物、越界修改、基线漂移和候选冻结后替换都会被拒绝；旧提示词流程继续通过。

### 第二步：接上移动问数真实运行

在业务项目的测试侧提供适配器，完成准备隔离环境、应用候选、读回生效配置、重置状态、运行问题、分页读取完整结果、恢复原版。先沿用现有 Python 测试适配器调用业务原有函数或命令；业务生产进程不安装 RSI。适配器只报告真实运行与结果，不能自行宣布候选通过独立验收。

首个候选以词典或指标上下文的等价修正为宜；同时保留一条原版重跑和一条故意返回不完整结果的拒绝路径。用户项目若只有共享可变配置，必须先建立隔离项目或等效保护，再进行候选实验。

**完成条件**：原版与候选在相同条件下真实运行，能证明实际加载了对应配置；完整结果与最终答复可复核；超时、截断、恢复失败分别有明确状态，不计作答对。

### 第三步：比较、独立验收和交付

共用内核继续掌管来源分组、训练/验证用途、验证次数、预算、候选冻结及独立验收。配置候选和提示词候选走同一防过拟合边界。训练明细可用于提案；验证只给汇总；独立验收材料由独立流程持有。输出按来源组呈现改善与退步，保留完整运行异常、费用和关键案例。

口径不变的候选可在原 Benchmark/Gold 和同一快照下成对比较。若公式、范围、时间、单位、NULL/0 或阈值等改变了正确答案，先由业务方确认正式规则，建立新 Benchmark/Gold 版本并在新口径下重跑原版；旧版与新版分数不能直接当作优化幅度。评分器或 Gold 修正也单独版本化并重跑基线。

**完成条件**：开发比较、独立验收、实际产品生效三种状态独立记录；验收失败或证据不足时不授予采用资格；交付物能脱离 RSI 运行并可恢复。

### 第四步：用第二个场景检验扩展接口

等真实问数闭环稳定后，将散落在 `workspace.py`、`verification.py` 和 Skill helper 中的 `ask-data` 特判收敛到显式场景接口，并保持旧入口兼容。新增一个确实不同的社区场景，用协议测试验证案例、结果、评分、候选范围和拒绝路径；若仍要修改共用验收规则才能接入，先修正接口。

**完成条件**：第二个场景无需复制来源隔离、验证账本、候选冻结或采用判定；外部场景包的加载与版本协议经过真实贡献再定稿。Go/Rust 独立核心或常驻服务只在跨语言接入出现实证瓶颈时评估。

## 最近一个可执行工作包

2026-10-03 已完成“**配置候选身份 + 本地隔离适配器**”的窄切片：等价别名修正走完原版/候选重跑，明确声明口径变化、越界路径/字段、原版漂移与恢复包替换被拒绝。范围检查和语义声明不能自动证明业务等价。下一工作包接移动问数测试环境，固定真实失败、完整结果和实际配置读取；再建立配置独立验收。保留当前已修改文件的状态，按归属审查后再提交；本计划本身不授权提交或推送。

## 不作为当前里程碑的事

- 自动搜索正式指标公式或临时修改 Gold、评分器来提高分数。
- 凭合成案例、HTTP 成功、模型自评或本机文件摘要宣称业务正确或独立验收完成。
- 先建插件市场、自动加载陌生代码、要求所有使用者采用 Python 业务栈，或让生产业务依赖 RSI 运行时。
