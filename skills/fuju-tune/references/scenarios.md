# 场景包贡献契约

主 `SKILL.md` 保留共用的真实重跑、训练/验证隔离、独立验收和交付规则。场景包只补充领域里的案例、输出、评分、失败分类、可调整对象和接入说明。社区贡献者新增一个目录即可被场景目录脚本发现；脚本只读文件，不加载或执行场景代码。

## 目录

```text
scenarios/
  ask-data/
    manifest.json
    guide.md
  <新场景 id>/
    manifest.json
    guide.md
```

场景 id 使用小写英文字母开头，之后只含小写字母、数字和连字符，最长 64 字符。目录与清单里的 `id` 必须相同。`guide` 是本目录下的 Markdown 文件名，不能指向外部路径或符号链接。清单示例：

```json
{
  "schemaVersion": 1,
  "id": "sample-domain",
  "title": "示例业务场景",
  "description": "检查此类 Agent 的真实业务结果。",
  "status": "draft",
  "guide": "guide.md",
  "targets": ["tool-config", "prompt"],
  "automatedTargets": []
}
```

`targets` 列出场景可提出的产品改动，`automatedTargets` 只列出当前工具能自动比较的对象。两者都用小写连字符 id；`draft` 的自动比较列表必须为空。智能问数支持提示词比较，以及通过显式文件候选比较词典、项目规则和指标上下文；文件模式见[接入与交付](file-candidates.md)，不代表自动生成配置或配置独立验收已完成。正式指标口径与代码改动尚未自动接入。`draft` 表示可读的场景提案；`integrated` 表示仓库已有经过测试的执行接入。两种状态都不是可信业务收益或独立验收证明。运行 `python <skill目录>/scripts/scenarios.py check` 校验全部清单；`list` 列出场景，`show <id>` 返回某个指南的绝对路径。这些命令不会导入 Python 场景模块。

## 指南应写清

1. 这个场景匹配哪些真实任务，用户程序的哪条入口要重跑。
2. 案例的来源、语义家族、标准答案或行为依据，以及何时必须重新核对答案。
3. 完整运行结果的格式；业务答错、工具运行异常、部分结果怎样区分。
4. 如何把候选交给真实程序、重置会话与状态、读取完整结果和恢复原版。
5. 可以调整哪些产品文件或配置，哪些是正式业务定义，哪些是固定评测依据；口径变化由谁确认。
6. 评分器及其版本、关键退步、训练反馈和验证汇总的边界。
7. 目前的执行能力与证据范围；还不能执行或没有独立验收时明确说明。

场景可引用共用的[接入契约](integration.md)、[业务案例](business-evals.md)和[独立验收](verification.md)，无需复制这些规则。贡献者可以提供适配器和评分器代码，但必须通过真实测试确认调用路径。不要把私有题、答案、客户数据、凭据或原始 Trace 放进 Skill。

## 运行能力与验收

场景目录是 Skill 的**说明与发现接缝**。当前可执行的领域流程是智能问数：调用 `run_experiment.py` 时传 `--scenario ask-data`。helper 会核对场景状态与 `AgentSpec.kind`；其他场景即使把清单改成 `integrated`，仍会在运行前被拒绝，直到对应执行接缝和测试进入仓库。清单中的 `status` 不会使 `fuju-rsi` 自动支持新的 `AgentSpec.kind`，也不会授予采用资格。缺少冻结数据、验证次数保护或独立验收边界时，先做开发诊断并说明限制；不要把场景改名为 `custom` 来绕开检查。

新增场景至少提供可运行的正常、答错、异常和不完整结果样例，以及来源隔离、验证次数和验收拒绝路径测试。核心负责候选冻结和采用判定，场景贡献者负责业务评分依据。详细投稿要求见仓库根目录的 `CONTRIBUTING.md`。
