# 问数场景调整什么

Fuju RSI 选择和检验的是**业务程序中可交付的改动**。问数场景里的主要对象通常是指标、词典和项目规则；提示词、检索配置或代码也可以是某次失败的真正原因。先看真实运行结果和依据，再决定改哪一层。不要为了让固定题目涨分，把评测题、Gold 或评分器当成候选改动。

| 对象 | 常见问题与允许的候选 | 需要特别核对 |
| --- | --- | --- |
| 指标配置 | 指标缺失、字段映射不全、模型可见说明不清 | 公式、范围、时间、单位、NULL/0、阈值及正式口径是否变化 |
| 业务词典 | 已确认的同义词、别名、枚举映射、概括性问法解释不足 | 新词是否真的等价；若扩大或缩小统计范围，按口径变化处理 |
| 项目规则 | 跨指标共同的统计时点、项目快照、澄清与结果表达规则未传达 | 是否与具体指标优先级冲突，是否改变正确答案或受影响题组 |
| 提示词、检索或代码 | 配置正确但模型没有用到、检索没召回、SQL 生成或结果交付有错误 | 候选是否真实进入最终调用；不能用提示词补丁掩盖错误业务定义 |

在移动问数 Benchmark 的现有项目中，正式指标来源是 `metric-definitions.xlsx` 和对应的 `metric-definitions.md`；`config/source/metric_context.json` 补充指标上下文与参考路径，词典补充在 `config/source/term_context.json`，跨指标规则在 `config/source/agent_rules.md`。生成的 `semantic_config.json` 是交付副本，应沿该项目现有准备脚本从来源重建。这个文件映射只适用于该项目；社区场景应声明自己的来源与生成关系，不把移动项目的文件名写成 RSI 通用接口。

## 改动类型决定能否沿用 Benchmark

**等价表达改进**：例如已核实的别名补充、说明文字澄清，且能证明答案所需的公式、范围、日期、字段、单位和空值规则不变。冻结原 Benchmark 与 Gold，在同一数据快照和运行条件下成对比较原版与候选，检查相关题及其他题的退步。即使分数提高，独立验收仍需单独执行。

**业务口径变化**：例如改公式、统计范围、项目取样、时间点、NULL/0、阈值或输出含义。这是业务规则修订，不是用旧答案搜索一个更高分配置。先记录原文、分歧、受影响案例和建议，由有权确认口径的人明确批准；然后更新正式来源、重新生成配置、刷新受影响的参考答案与 Benchmark 版本、重新跑原版。新旧版本分数不能直接当作同一规则下的收益。无法证明等价时，按此类处理。

**评测规则错误**：Gold 或评分器确有错误时单独修正并记录依据，在新规则下同时重跑原版与候选。不能为了让某个候选通过，直接改答案、删题或忽略失败。

## 候选交付包

一个候选可以包含多个相互依赖的文件，但要作为**一个版本**比较和恢复。建议记录：目标类型与允许改动的文件、原始版本及文件摘要、候选差异、等价或口径变化判断及依据、生成配置的命令与产物摘要、隔离测试环境、数据和模型条件、影响的来源组、回退方法。多文件候选不能只记录一个提示词字符串。

运行前先构造隔离的候选配置；确认测试实例实际加载了该版本，不让其他会话读到实验中的共享配置。用同一冻结 Benchmark、同一数据快照和相同评分规则重跑原版与候选，核对完整 SQL 结果和最终答复。结果报告分别写出业务正确率、运行异常、关键案例退步、未判分题和已知费用。

**当前实现边界**：词典、项目规则和指标上下文支持[文件候选比较](../../references/file-candidates.md)，以版本化身份绑定多文件内容、允许改动范围和原版，并在独立目录成对重跑、核对实际读取摘要、交付差异及恢复包。Skill 使用 `--candidate-kind files`，CLI 使用 `compare-files`。当前只提供开发/回归证据，结果始终 `adoptable=false`；配置独立验收、正式发布、代码候选与自动生成尚未开放。不能把提示词搜索或本地文件摘要当作配置独立验收凭据，也不能输出“配置已由 RSI 独立验证”。
